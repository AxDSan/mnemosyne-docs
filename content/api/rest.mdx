# HTTP Interfaces

<Callout type="warning" title="There is no general-purpose REST API">
This page previously documented a FastAPI CRUD server with `POST /store`, `POST /recall`, a `mnemosyne/server:latest` Docker image, a `python -m mnemosyne --host --port` start command, and Swagger endpoints. **None of that exists in the codebase.** There is no `__main__.py`, no such Docker image, no `serve` or `api` command, and no `MNEMOSYNE_CORS_ORIGINS` variable.

If you were building against those endpoints, they never shipped. Use the [Python SDK](/api/python-sdk), the [MCP server](/api/mcp-server), or the [Hermes plugin](/api/hermes-plugin) instead.
</Callout>

Mnemosyne is a library, not a service. It exposes three narrow HTTP surfaces, each for a specific job, and none of them is a memory CRUD API.

## 1. Sync server

A deliberately minimal server built on the Python standard library. No FastAPI, no external dependencies. Its only purpose is replicating a shared surface between your own devices.

<CodeBlock code={`mnemosyne sync-serve \\
    --db-path /path/to/surface.db \\
    --host 127.0.0.1 \\
    --port 8765 \\
    --api-key-file /path/to/api-key`} language="bash" />

| Endpoint | Method | Purpose |
|---|---|---|
| `/sync/pull` | POST | Pull events from the server's event log |
| `/sync/push` | POST | Push local events to the server |
| `/sync/status` | GET | Device id, cursor, event count, encryption state |
| `/healthz` | GET | Liveness probe |

Authentication is a bearer API key or a JWT, supplied on the command line rather than by environment variable. Point `--db-path` at a dedicated shared-surface database, never a private one.

This is a management API, not a general HTTP service. It cannot store or search memories. See [Sync](/operations/sync).

## 2. Memory browser

An optional read-only web UI for inspecting what is in your database.

<CodeBlock code={`pip install fastapi uvicorn
mnemosyne-browser`} language="bash" />

It is a separate console script, not part of the core install, and it opens databases read-only. It is for looking, not for writing. There is no stable HTTP contract; treat it as a UI, not an API.

## 3. MCP over SSE

The MCP server supports an SSE transport for clients that cannot use stdio.

<CodeBlock code={`mnemosyne mcp --transport sse --port 8080`} language="bash" />

This speaks the Model Context Protocol, not REST. Tools are invoked as MCP tool calls. A non-loopback bind requires `MNEMOSYNE_MCP_TOKEN`.

This is the closest thing to a remote memory API, and it is the one to use if you need network access to memory operations. See the [MCP server reference](/api/mcp-server) and the [tool schema](/api/tool-schema).

## Which one do I want?

| Goal | Use |
|---|---|
| Store and recall memories from another machine | [MCP over SSE](/api/mcp-server) |
| Store and recall memories in the same process | [Python SDK](/api/python-sdk) |
| Keep two of your own devices in sync | [Sync server](/operations/sync) |
| Look at what is stored | `mnemosyne-browser`, or `mnemosyne stats` |
| Integrate with a Hermes agent | [Hermes plugin](/api/hermes-plugin) |
