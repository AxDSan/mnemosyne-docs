# Configuration

Mnemosyne is configured via environment variables and (in Hermes Agent) through `config.yaml`. All settings have sensible defaults so you can get started with zero configuration.

## Constructor Parameters

The only runtime parameters are passed directly to the `Mnemosyne()` constructor:

```python
from mnemosyne import Mnemosyne

mem = Mnemosyne(
    session_id="my-agent",   # Scope working memories to this session
    db_path="./data/mem.db", # Custom database path (optional)
)
```

| Parameter | Type | Default | Description |
|-----------|------|---------|-------------|
| `session_id` | `str` | `"default"` | Session identifier for scoping working memories |
| `db_path` | `str | None` | `None` | Path to the SQLite database file |

## Hermes Provider Config (config.yaml)

These keys live under `memory.mnemosyne` in Hermes Agent's `config.yaml`.

| Key | Default | Description |
|-----|---------|-------------|
| `auto_sleep` | `False` | Auto-run sleep() when working memory exceeds threshold |
| `sleep_threshold` | `50` | Working memory count before auto-sleep triggers |
| `vector_type` | `int8` | Vector storage type (float32, int8, bit) |
| `ignore_patterns` | `[]` | Regex patterns to filter from memory storage |
| `profile_isolation` | `False` | Per-profile memory isolation via Mnemosyne banks |
| `shared_surface_path` | `data/shared/mnemosyne.db` | SQLite path for shared surface memories |
| `shared_surface_read` | `False` | Merge shared-surface results into private bank recall |
| `skip_contexts` | `cron,flush,subagent,background,skill_loop` | Agent contexts to skip Mnemosyne init |
| `sync_roles` | `['user', 'assistant']` | Conversation roles to autosave in sync_turn() |

### Embeddings & Vector Search

Mnemosyne uses **BAAI/bge-small-en-v1.5** via fastembed (384 dimensions) for local embedding generation. No external API key is needed.

| Variable | Default | Description |
|----------|---------|-------------|
| `MNEMOSYNE_VEC_TYPE` | `int8` | Vector storage format (int8, float32, float16, binary) |
| `MNEMOSYNE_EMBEDDING_MODEL` | `BAAI/bge-small-en-v1.5` | fastembed model for vector embeddings |
| `MNEMOSYNE_EMBEDDING_DIM` | `384` | Override embedding vector dimension |
| `MNEMOSYNE_EMBEDDING_API_KEY` | — | API key for cloud embedding provider |
| `MNEMOSYNE_EMBEDDING_API_URL` | `https://openrouter.ai/api/v1` | API endpoint for cloud embeddings |
| `MNEMOSYNE_NO_EMBEDDINGS` | `false` | Disable dense vector retrieval entirely |
| `MNEMOSYNE_EMBEDDINGS_VIA_API` | `false` | Force cloud API mode for embeddings |

### LLM Configuration (Sleep Summarization)

The sleep cycle uses an LLM to summarize grouped working memories before promoting them to episodic memory. Can run locally or via an external API.

| Variable | Default | Description |
|----------|---------|-------------|
| `MNEMOSYNE_LLM_ENABLED` | `true` | Enable LLM summarization during sleep consolidation |
| `MNEMOSYNE_LLM_BASE_URL` | — | OpenAI-compatible API base URL for remote LLM |
| `MNEMOSYNE_LLM_API_KEY` | — | API key for remote LLM endpoint |
| `MNEMOSYNE_LLM_MODEL` | — | Model identifier for remote LLM calls |
| `MNEMOSYNE_LLM_MAX_TOKENS` | `2048` | Max output tokens per LLM summary |
| `MNEMOSYNE_LLM_N_CTX` | `2048` | Context window size for local LLM |
| `MNEMOSYNE_LLM_N_THREADS` | `4` | CPU threads for local LLM inference |
| `MNEMOSYNE_LLM_REPO` | `openbmb/MiniCPM5-1B-GGUF` | HuggingFace repo for GGUF model |
| `MNEMOSYNE_LLM_FILE` | `MiniCPM5-1B-Q4_K_M.gguf` | GGUF filename for local LLM |
| `MNEMOSYNE_LLM_FALLBACK_BASE_URL` | — | Fallback API URL when primary remote LLM fails |
| `MNEMOSYNE_LLM_FALLBACK_API_KEY` | — | API key for fallback LLM endpoint |
| `MNEMOSYNE_LLM_FALLBACK_MODELS` | — | Comma-separated fallback model names |
| `MNEMOSYNE_FORCE_LOCAL` | `false` | Skip remote LLM and use local model directly |
| `MNEMOSYNE_LLM_CONFLICT_DETECTION` | `false` | Enable LLM-based conflict detection during sleep |
| `MNEMOSYNE_CONFLICT_LLM_BASE_URL` | — | API base URL for conflict detection LLM |
| `MNEMOSYNE_CONFLICT_LLM_API_KEY` | — | API key for conflict detection LLM |
| `MNEMOSYNE_CONFLICT_LLM_MODEL` | — | Model for conflict detection LLM calls |
| `MNEMOSYNE_HOST_LLM_ENABLED` | `false` | Route consolidation through host-provided LLM adapter |
| `MNEMOSYNE_HOST_LLM_MODEL` | — | Model override for host LLM adapter |
| `MNEMOSYNE_HOST_LLM_PROVIDER` | — | Provider override for host LLM adapter (e.g. openai-codex) |
| `MNEMOSYNE_HOST_LLM_N_CTX` | `32000` | Context window budget when using host LLM adapter |

Any OpenAI-compatible endpoint works here — a local `llama.cpp` or vLLM server, or a hosted provider. For example, with [Atlas Cloud](/partners/atlas-cloud) (a compute partner):

```bash
export MNEMOSYNE_LLM_BASE_URL=https://api.atlascloud.ai/v1
export MNEMOSYNE_LLM_API_KEY=your-api-key
export MNEMOSYNE_LLM_MODEL=deepseek-v3
```

Leave `MNEMOSYNE_LLM_BASE_URL` unset to keep consolidation entirely local (GGUF model, then AAAK extractive compression).
